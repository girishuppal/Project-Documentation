|Diagram | Description
|---|---|
|**Class Diagram** | Maps out the static structure of a system using classes, attributes, operations, and relationships between classes|
|**Object Diagram** |Shows a snapshot of the system at a specific point in time using actual instances of classes and their current values |
|**Component Diagram** | Illustrates the organization, modular parts, and dependencies of physical or software components|
|**Deployment Diagram** | Depicts the physical hardware nodes and how software components are deployed across them|
|**Package Diagram** | Organizes system elements and classes into logical groups or folders to manage dependencies and namespaces|
|**Use Case Diagram** |Depicts functional requirements by showing the interaction between external actors and system use cases |
|**Activity Diagram** | Illustrates sequential and concurrent workflows, business processes, and step-by-step control flows|
|**Sequence Diagram** | Shows how objects interact in a sequential order by passing messages over time|
|**Collaboration Diagram** | Focuses on the structural organization of objects and the numbered messages they exchange|
|**Timing Diagram** | Focuses specifically on time-critical behavior, showing how object states or messages change along a linear time axis|
